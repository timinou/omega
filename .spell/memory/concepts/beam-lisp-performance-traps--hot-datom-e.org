Observed 2026-10-03 (omega pin 2360b32e, beam-lisp main 766fcb93), PLAN-003 spikes:
- A datom entity updated N times costs O(N) to `entity`-read and to `transact!` (100 updates: 9/46 ms; 1600: 161/514 ms), memory and fjall alike. `lookup-ref` stays O(1). Design rule: append-only facts for anything that moves (refs, heads, cost, cursors). BUG-002.
- Datalog joins are 10–70× slower than raw index reads: 602 turns, a 4-clause query 1.4 s vs `(datom/datoms db :avet attr v)` 20 ms. Use raw indexes on hot paths.
- A beam-lisp `atom` deref copies the whole value out of a NIF cell (O(size)): 10k-entry map, 100 reads 109 ms vs 0.3 ms in the process dictionary. Caches belong in a process.
- A process-dictionary cache is exact only in its owning process. A reader in another process silently sees a stale view (the C8 prototype's poller saw `:turns 0`). Prefer loop-local values threaded through the owner's code.
- omega ext `:on` handlers run in spawned processes after the task has moved on. They are inexact for per-step work; use a `:tool/after` hook (inline), and cast heavy work to one owner process.
- Runtime redefinition: `(BeamLisp.Compiler/eval_string "(ns X) (defn f …)")` takes ONE arg, leaves the current ns switched (end with `(ns <mine>)`), and is VM-global. There is no `alter-var-root`; restore by re-evaluating the original source text.
- `clojure.string/replace`, not `replace`; there is no `take-last`/`ffirst`/`resolve`/`dotimes`. `datom/transact!` needs integer negative `:db/id` (string tempids are rejected). `clojure.edn/read-string` ignores `:readers`.
