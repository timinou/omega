Observed 2026-10-01 on beam-lisp main 59cdb542 (bin/bl, running from source): `(println (f 1) (f 2) (f 3))` with f logging → log [3 2 1]. Args evaluate RIGHT-TO-LEFT (Erlang argument evaluation is unspecified; the compiler emits a plain call). Clojure guarantees left-to-right. Consequence: `(println (reg/register r p a) (reg/whereis r q))` ran whereis BEFORE register and looked like a proc.reg bug — it was not. Rule for omega code: never rely on argument evaluation order for side effects; sequence effects with `let`/`do`. Worth an upstream bug in beam-lisp.
