* Symptom (OBSERVED 2026-10-03, omega pin 2360b32e)

Two task systems in ONE BEAM VM, two different roots, two in-memory envs. Each opens its first task, so both are `t-1`. A's cell sleeps then writes `a.txt`; B's task opens in between and writes `b.txt`.

```
ids      : t-1 t-1
A root   : []
B root   : ["a.txt" "b.txt"]
A claims : 0
B claims : 2
```

A's eval ran with B's system: B's root, B's env, B's claims. **Project A's agent wrote into project B.** Sequentially, a `def` in A's t-1 is also visible to B's t-1 (`"b sees secret=from-a"`).

Reproduce: the `omega.ed.probe.shared-vm` block in research/domain/interface/bl-ed.bl.md §8.3 (`bin/bl run research/domain/interface/bl-ed.bl.md`).

* Cause

- `omega.prelude/SYSTEMS` and `DONE` are atoms keyed by task id (`src/omega/prelude.bl:21-24`). Task ids come from a per-env counter (`omega.env/counter-ids`), so they are unique per world, not per VM.
- `omega.codemode/task-ns` = `omega.task.<id>` (`codemode.bl:48`): one namespace per id per VM.
- `omega.stream` uses one pg group `:omega/stream` per node: every watcher receives every world's deltas.

* When it matters

Any VM that hosts two omega worlds:
- beam-lisp realm's shared mode (`:vm "shared"` / `--share-vm`, PLAN-158), once omega runs on a shared warm VM;
- tests or tools that start two systems in one VM.

The default today is one VM per tree, so a normal `bin/omega` run is not affected.

* Fix (core change C2 in bl-ed.bl.md §8.4)

Qualify by world:
- `world-id` = the realm id, or a fresh token for an in-memory env, stored on the env map;
- `SYSTEMS`/`DONE` keyed by `[world-id task-id]`, and `-bind!` puts the world id in the process dictionary next to `:omega/task`;
- `task-ns` = `omega.w.<world>.<task>`;
- stream group = `[:omega/stream world-id]`, with `watch!` taking the world.

* Acceptance

- The §8.3 probe, turned into a test: A's root holds exactly `a.txt`, B's root holds exactly `b.txt`, and each env holds exactly its own claim.
- A `def` in one world's t-1 is not visible in another world's t-1.
- A stream watcher of world A receives no deltas from world B.
- The existing suite and `omega.bl.md` are unchanged.

* Until fixed

Declare `:vm "own"` for omega projects (the realm default).
