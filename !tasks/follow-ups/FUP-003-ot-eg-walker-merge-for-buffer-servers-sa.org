* Context

Design: research/domain/interface/bl-ed.bl.md §5. Buffer servers (one defserver per file in use) rebase each actor's ops by position shifting (spike 1, §5.3) and keep the op log as datom facts (spike 2, §5.5). Position shifting handles non-overlapping concurrent edits and exact-replacement compare-and-set. It does NOT handle:

1. Two actors inserting at the same position concurrently: order depends on arrival, so it is nondeterministic for the actors' intent. Needs a tiebreak (by actor id) at minimum.
2. A console replica that diverged for long (offline, slow link): rebasing N ops over M ops is O(N·M) shifts and loses intent on overlapping deletes.
3. Overlapping delete/replace from two actors: today the second one's span collapses to the first's end.

* Goal

Replace `transform` in the buffer server with a proper merge that keeps the op log as the source of truth.

* Candidate

Eg-walker (Gentle & Kleppmann 2024, https://arxiv.org/abs/2409.14252): it replays an event graph only when branches diverge. The steady state is plain text plus an op log, which is exactly what the buffer server already stores. The steady-state memory is an order of magnitude below CRDTs, and merging long branches is much faster than OT.

* Acceptance

- Property test: for any two op sequences from two actors against one base, both arrival orders converge to the same text (TP1), and each actor's inserts stay contiguous.
- Spike 1 and spike 2 in bl-ed.bl.md still produce the same observed output.
- Same-position concurrent inserts are ordered deterministically by actor id.
