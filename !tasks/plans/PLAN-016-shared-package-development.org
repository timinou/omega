#+status: IN_PROGRESS

* Outcome and scope
One Omega application host serves editor sessions that load packages. PELAGIC
is a package/preset; standalone demos export the same frontend with a local
adapter. Package loading must not create a project realm or backend world.
Generic runtime/compiler improvements go upstream and are committed there.
Omega pins the committed upstream release only after integration tests verify
the BEAM host and the newly compiled JS graph; evidence below records each gate.

This replaces the source-inspection-only ordering in the first version of this
plan. Detailed experiments and raw evidence: research/realm-prototype/README.md.
Coordinate compiler/actor consolidation with PLAN-014; do not introduce another
scheduler, value representation, namespace reader or package lifecycle.

* The architecture we should actually integrate
- OS VM: one release build, optionally shared by multiple project realms.
- Project realm: source/declaration identity, Env, index, owned service members.
  Reuse existing vm.realm/vm.manager/vm.owner; these mechanisms work.
- Omega world: its document root, durable/memory store and task system. World
  identity need not equal the source project's realm identity. Multiple worlds
  may be owned services under one Omega application realm when appropriate.
- Editor session: package state, keys/layout layers, audio and browser jobs.
  Unuse closes its resources; it does not retire backend application modules.
- Browser realm: immutable module instances and eligible CPU workers. Different
  tabs are different realms. Worker crossings require real messages/transfers;
  same-realm native calls use the existing canonical actor/value ABI directly.

Prefer one warm Omega application realm and host for ordinary package sessions.
The prototype's two project realms tested isolation; duplicating Omega's source
load for every package/tab would reproduce its expensive first-load costs.
Do not use :uses as verified code sharing until its admission is implemented.

* Step 1 — persistent service task semantics, before changing env.bl defaults
Owners: upstream task/VM integration, then Omega launcher.

The retained-service warm path is proven with an explicitly started daemon.
The first-ever launch prototype separately demonstrated that current shared
Start policy launches a daemon in the background while THIS first command runs
cold. Its service disappeared when the task returned and the launcher halted
that VM. Introduce or reuse a generic service-task path that ensures the owner VM
is ready and attaches before starting the service. Do not equate :warm "start"
with a persistent service guarantee. Ordinary finite tasks keep their current
fast cold fallback behavior; --cold service behavior must be explicit.

Implement acquisition around existing manager/owner primitives, not an Omega
process registry. manager/serve alone spawns each time; it does not deduplicate.
Identity covers application realm, world root, storage/model mode, backend
revision and frontend compatibility. Store a STARTING reservation before the
request can die, then publish READY only after successful initialization.

Test caller disconnect during startup, competing acquire, startup failure,
service crash/reacquire and acquire against realm close. Decide whether a lost
caller cancels startup or leaves an owned startup to finish; enforce it once.
No abandoned service and no two writers to the same durable world.

Use a stable service IO/log owner instead of assuming a command's wire group
leader lasts forever. Preserve cwd, source-resolution and environment bindings.
Keep full foreground launch with Ctrl+C and a documented warm-service stop verb.
Avoid kill-only production shutdown: stop admission, finish/cancel work, flush
storage, stop HTTP/task resources, release leases, then retire realm code.

Accept: first-ever and subsequent root launch both leave exactly one live host;
commands return links; realm/service tools can inspect and stop it; no orphan
listeners, task processes or durable handles. Hot launch P95 goal <500 ms on
recorded hardware; report misses honestly. Fast browser unuse is independent
from the measured slow backend realm retirement.

* Step 2 — service-owned routes and root tasks
Owners: upstream vm.ports/vm.gateway lifecycle; Omega session preset policy.

Retain e8ffb744's root check. Add explicit claim generations/owner leases so a
service or realm ending retracts its claim while the shared OS PID stays alive.
Do not use OS PID liveness as sole service liveness. Make release conditional
on the current lease; a late old service cannot erase its replacement's route.

Serialize hostname admission across cold OS processes, not just a BEAM global
lock. Duplicate host claims must conflict with an actionable explanation.
Port claiming is currently a bind probe followed by close; coordinate claiming
and actual listener readiness and recover cleanly from bind races.

Use existing gateway claims, not a second proxy. Root tasks select session
presets on one Omega host. A hostname maps to a port, not to a layout/query:
explicitly implement preset selection (for example a root-page redirect) when
several friendly names point at the same host. Keep direct localhost URLs.

Existing, tested declaration vocabulary is :vm "shared", :warm "start"/"attach"
and :tasks {name {:run "file.bl"}}. Add new service-task metadata only with
upstream parser, launcher and lifecycle support. Do not publish unsupported
:service syntax as if it already worked.

pelagic.dev and spikes.pelagic.dev can be root task names selecting package,
layout and document. Friendly domains are a separate route declaration. .dev
hostnames need browser-compatible local TLS/resolution; prove the gateway/CA
setup first and provide the established local naming fallback.

Accept: two roots cannot steal claims; close/restart never leaves stale or
misdirected names; duplicate hosts and unrelated listeners are rejected; aliases
open different session presets on the SAME host, without world activation.

* Step 3 — cold application loading and verified shared code
Owners: upstream application.package/AOT, realm declaration and loader.

Profile the 25 s first runtime task and 80/30 s Omega host startup by phase.
Do not attribute all of it to realm creation. Separate index initialization,
source/ANF compilation, application initializers, dependency startup and IO.

First evaluate the existing application.package and realm-aware artifact path
against Omega, using current upstream realm package tests as contracts. Ship
closed, admitted code with the application instead of compiling it on every
fresh realm. Initialization still runs under the target world's environment;
never capture live sockets, mutable world state or secrets in artifacts.

For :uses, wire declared resolution paths, verify actual transitive source/
macro/compiler closure hashes before publication, enforce tier/shared-only
references and define initializer/var ownership. Reject false hashes, modified
sources and same-prefix/different-full-hash conflicts. Test two roots with one
shared pure library, then a stateful initializer and a forbidden realm reference.
Do not share merely because namespace strings match or attach an unverified
content label to globally published code. This gate is required for cross-
project code sharing, not for many sessions using one existing Omega realm.

Accept: admitted Omega libraries reuse compatible code without reusing mutable
world state; incompatible revisions refuse or isolate. Report cold load,
compiled-unit counts, memory and initialization parity with source mode.
Keep a correct source fallback for non-admitted dynamic code.

* Step 4 — declarative frontend assembly and coordinated artifacts
Owner: Omega package metadata; generic artifact support upstream as useful.

Extend the EXISTING package manifest with a versioned frontend declaration:
entry/roots, preload/host contracts, actor entries, assets/documents and loader.
Layout stays in bl-package :provides; backend activation remains independent.
Migrate PELAGIC/catalog first and one representative backend package second.

Build a union namespace graph and canonical actor/native runtime once for the
configured package set. Modules load by session; package loading does not run
a shell installer or imply new backend realms. Standalone export adds only its
storage/offline adapter and ZIP around the same generated package graph.

Extract current content fingerprints, SHA inventory and immutable generations.
Coordinate concurrent cold builds across OS processes, use unique staging and
atomic publication, recover abandoned stages and preserve hosts' pinned
artifacts. Prune only unreferenced generations with a bounded retention policy.

Accept: metadata-only package assembly, no vendor output mutation, matching
server/demo modules, corrupt-cache recovery, one publication under concurrent
builds and exact per-editor use/unuse behavior.

* Step 5 — incremental compiler, then transactional watch
Owners: upstream bl.js/compiler and actor linker; Omega adoption protocol.

Record actual dependencies before caching: source resolution, discovered module
references, macros/helpers, core/seed ABI, host contracts, typed/system facts,
actor suspension/callback exports, preloads and runtime identity. The current
compiler discovers edges beyond :require and uses isolated Env forks.

Cache serializable read/prepare/ANF/emission products, never live Env references.
Start with conservative transitive invalidation; narrow by ABI only after tests
prove callers' optimization facts remain valid. Re-run complete linking and
native manifest audits. Exclude launch/build helper files not actually read by
the graph. Clean and incremental builds must have identical behavior/errors.

Reuse existing watcher notifications but do not equate watch-task rerun with
browser HMR. Debounce, cancel obsolete speculative builds and publish immutable
validated generations. Sessions keep their working generation until adoption.
CSS/docs can refresh; shaders validate before swap; arbitrary code changes need
explicit migration/replacement or a session reload. Bound retained ES module
generations, which imports cannot unload.

Use PELAGIC safe audition to prepare/validate a candidate, commit on an approved
beat boundary or cancel/stale it. Bad code must preserve active playback.
Accept: smaller edits rebuild fewer namespaces with recorded cache explanations;
rapid edits publish only latest valid candidates; repeated replace/unuse does
not drift keys, layouts, resource counts or active audio.

* Step 6 — actor CPU leases and playback pressure tests
Owners: upstream canonical JS actors; PELAGIC first client.

Preparation currently initializes once, uses job ID 1 and terminates on done.
Make jobs reusable with owner/generation IDs, bounded inbox/credit, reset
acknowledgement, cancellation and stale-result fencing. Pool within a browser
realm first; keep AudioWorklet and canvas/GL resources dedicated initially.

Use BL modules lowered through the canonical JS/actor ABI for admission,
priorities, fairness and audio reserve. Defaults should remove per-namespace
scheduling boilerplate. Same-realm calls retain native identity; worker leases
do not pretend to eliminate transfer/serialization. Cooperative bounded turns
cancel CPU work; terminate/replace a worker that cannot yield. Measure actual
CPU cessation separately from merely ignoring a cancelled result.

Accept: two sessions cannot observe each other's jobs; unloading A leaves B
playing; crashes recover; worker/retained-byte counts plateau over 100 cycles;
preparation digests match. Measure competing compilation/export/analysis bursts,
reserve minima, CPU, queue delay and cancellation tails before picking pool size.
Cross-tab SharedWorker remains optional and needs its own browser/transfer proof.

* Final integration and evidence
For each step: commit generic fixes upstream, integrate Omega against committed
revisions, update this file and link reproducible evidence. Do not push unless
separately requested. Preserve unrelated work; one owned BL VM job at a time,
inspect scripts/bl-mem, cap long jobs and stop owned test services.

Required integration gates: new-pin JS compile and actor/native ABI checks;
Omega/package/editor tests; unchanged presentation equivalence; used/unuse
screenshots in the real editor; two audible sessions; safe audition commit/
cancel/stale tests; export integrity; repeated lifecycle and startup races.

Report P50/P95/P99/max, dropouts, startup, memory and resource counts. Separate
backend CLI/retirement time, browser scheduling, output audio clock and displayed
frame acknowledgement. Physical A/V <=16 ms remains a desired target that needs
repeatable external capture; browser clocks alone do not prove it. Profile FFT
allocation/plans and other CPU work before changing native/JS lowering.

Delete superseded installers, scheduler/control paths and duplicated pipelines
after their consumers migrate, then audit PLAN-014's remaining consolidation.
Explain new task syntax, service/session ownership, cache invalidation and reload
limits with concise executable examples and an actual PELAGIC demo.
