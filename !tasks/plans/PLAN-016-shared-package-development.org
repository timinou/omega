#+title: Shared Omega package development: warm tasks, incremental JS and owned actors
#+status: PLANNED
#+date: 2026-10-10

* Outcome
One Omega application, with packages loaded per editor session. Root BL tasks
select a session experience, not a separate application runtime. Shared build,
language and actor infrastructure lives upstream; Omega owns package assembly
and worlds; PELAGIC supplies readable BL domain modules and thin browser IO.
Standalone demos remain an export adapter over the same package graph.

This plan follows PLAN-015 and coordinates with, rather than replaces,
PLAN-014's unfinished actor/compiler consolidation. Do not create another
actor scheduler, value representation, package reader or private editor loop.
Upstream implementation and commits are authorized. This document is a plan,
not a claim that its phases or performance targets have been implemented.

* Investigation and evidence
Inspected Omega at 34c7a5d and upstream Beam Lisp at 48db7435. Source inspection
only in this round; measurements below are the previous recorded baseline,
not fresh benchmark results. Upstream has advanced beyond Omega's 797dc039 pin.

* Architecture and invariants
- Build identity includes compiler/runtime ABI, canonical inputs, options,
  resolution precedence and generated native/actor manifests.
- One build's warm VM can contain multiple project realms; a realm can own
  Omega services; a world owns durable task state; an editor owns its packages.
  These are distinct identities, not one global mutable application.
- Browser realm shares immutable modules and eligible compute workers. Each
  session owns editor state, audio, audition, revision and cancellable leases.
- Cross-tab sharing is a separate opt-in experiment. Do not claim ordinary
  Worker reuse crosses tab realms or requires no serialization.
- Ordinary BL and annotated JS interop use the canonical actor/value ABI.
  Native same-realm calls must not acquire a fabricated transport envelope.
- No test writes to the user's world on 8790. Use owned offline memory worlds.
- Follow the real bl-package contract, pkg-state ownership, layered bindings,
  provided layouts, effect-based IO and exact unuse. Document vendor changes.
- Last valid frontend generation remains usable after a failed build/reload.
  Audio keeps playing during build failures and speculative preparation.

* Phase 0 — compatibility and reproducible measurements
Owner: upstream integration + Omega. First implementation commit.
- Compare pinned APIs against current upstream: bl.js facade, actor native
  ABI, numeric contracts, reader, task CLI, shared VM and realm ownership.
- Run targeted upstream tests before proposing a new immutable Omega pin;
  build the actual release launcher too. A source checkout deliberately has
  a different endpoint policy and cannot prove release-wide VM sharing.
- Instrument CLI resolution, attach/boot, realm open, input scan, artifact
  verification, compile, link, staging and host acquire as separate timings.
- Run 30 warm repetitions and a small explicitly cold sample set, recording
  machine load, compiler identity, RSS+swap, graph bytes and peak resources.
- Prepare fixtures: unchanged; asset edit; private function edit; exported
  arity edit; macro/helper edit; host allowlist edit; namespace resolution
  change; corrupt cache; concurrent build; failed build.
Accept: baseline JSON and a compatibility matrix, with pin upgrade gated by
Omega/Pelagic/editor regressions. No indiscriminate latest-pin switch.

* Phase 1 — warm task and realm-owned Omega service
Owner: upstream vm/CLI where missing; Omega launch policy.
- Use existing shared VM declaration (:vm "shared", :warm "start") only after
  Phase 0 proves the selected release supports it. Keep --cold available.
- Implement host acquire/release through the existing manager/service owner:
  stable key from root, world configuration and frontend compatibility.
  Register server, task system, watchers and storage as owned resources.
- Return the URL from a warm task instead of parking its command process.
  Preserve a foreground cold form with explicit Ctrl+C lifecycle semantics.
- Concurrent acquire must yield exactly one host/world; creator death must
  clean up or allow takeover. Realm close drains its members, not other roots.
- Reuse vm.ports/vm.gateway claims where supported. Publish session routes to
  one host rather than opening a host per package. Keep localhost URLs usable.
- pelagic.dev and optional spikes.pelagic.dev are task aliases selecting
  package/layout/document. Friendly hostnames are route names, not task names.
  pelagic.dev as a hostname needs local resolution and browser-compatible TLS;
  do not promise that a task declaration alone configures either. Start with
  the gateway's established naming and expose a tested custom-domain option.
- Report status and stop through existing bl realm/bl vm tooling; avoid a
  second Omega process registry. Diagnose existing HTTP date-cache warnings
  through correct dependency application startup, not logger suppression.
Accept: warm compatible-host task P95 target <500 ms after initial attachment
and cache warmup, measured end to end; service persists after command return;
two roots remain isolated; conflicts, disconnect, startup races and shutdown
leave no orphan world, port or storage handle. Target is provisional, not SLA.

* Phase 2 — one declarative package frontend
Owner: Omega; generic cache/publication support upstream where appropriate.
- Extend existing package metadata with a versioned :frontend declaration;
  don't establish a parallel package format. Resolve paths relative to its
  manifest, validate escapes, duplicate namespace/asset names and ABI conflicts.
- Declaration covers namespace roots/entry, explicit preload/host references,
  actor entries, copied assets/documents, exported loader and optional demo
  adapter. Layout remains in bl-package :provides, not duplicated in metadata.
- First migrate PELAGIC and catalog, then one representative existing package
  with a backend. Backend activation remains independent from editor loading.
- Build one union graph for the configured package set and one shared runtime.
  Load modules per session; do not silently eagerly initialize every package.
- Extract Pelagic's fingerprint, inventory and immutable generation logic;
  retain cryptographic integrity, compiler identity and source-race detection.
- Add cross-process build coordination keyed by graph identity: unique staging
  paths, crash-recoverable ownership, waiting readers and atomic publication.
  A BEAM global lock alone cannot coordinate independent cold OS processes.
- Keep pinned generations alive while hosts/exports reference them; prune only
  unreferenced generations with clear retention limits. Local ZIP consumes the
  exact assembled generation, adding only its document/offline adapters.
Accept: manifest-only package addition works without another shell installer;
two simultaneous cold builds publish one valid artifact; failed/corrupt builds
recover; direct server and demo use identical package/runtime modules; no writes
to vendor output; catalog still loads/unloads per editor without activation.

* Phase 3 — sound incremental bl.js compilation
Owner: upstream js.build, shared compiler stages and canonical actor linker.
- Expose a dependency/build report before caching: source bytes, resolver
  inputs, discovered module-name refs, macro/helper dependencies, preloads,
  host declarations, core/seed links and exported native ABI metadata.
- Separate read/prepare, expansion/ANF, link context, JS emission and artifact
  assembly. Cache serializable compiler products, never live Env closures or
  process-local references. Restore staging in isolated Env forks.
- Begin conservative: namespace edit invalidates its transitive dependents;
  macro/helper and core/runtime changes invalidate every affected consumer.
  Introduce ABI-sensitive narrower invalidation only with evidence and tests.
- Include actor suspension/callback/export facts in invalidation. A private
  implementation change may still change optimization facts used by callers.
- Whole-graph linking, unresolved-name audit and native-manifest validation
  still run; a cache hit must not hide a removed export or forbidden JS access.
- Runtime/target/options changes invalidate the appropriate caches. Asset-only
  edits never enter the compiler. Exclude launcher/build helpers unless the
  compiler actually reads them as inputs.
Accept: clean and incremental builds behave identically for all Phase 0
fixtures, including negative diagnostics; report cache hit/miss explanations
and compiled namespace counts. Initial performance aim: >=5x reduction for a
small leaf edit on the same hardware; report achieved values without relaxing
correctness for the target. No cache optimization that forks the actor backend.

* Phase 4 — transactional watch and safe package replacement
Owner: Omega watcher/package lifecycle; PELAGIC audition integration.
- Reuse upstream watch notifications; debounce and coalesce edits, cancel
  obsolete speculative builds and fence results with input/generation IDs.
- Publish an immutable new frontend only after successful validation. Existing
  sessions stay pinned until they explicitly adopt an eligible generation.
- Classify changes: CSS/document refresh; shader validate then swap; code or
  ABI change requires package replacement or a session reload. Don't pretend
  every module can safely patch arbitrary closures.
- Use versioned module URLs consistently for the graph, including shared
  dependencies. ES module imports cannot unload cached old versions; bound
  replacement count and offer an explicit reload when retention grows.
- Prepare a candidate package, validate resource/schema compatibility and use
  existing safe audition for performance changes. Commit at an approved beat
  boundary; retain original on compile, shader, state or migration failure.
- Cancel candidate work on source change, unuse or lost session. Never migrate
  editor state via arbitrary map merge; package owns explicit migrations.
Accept: rapid edits publish only latest valid candidate; bad code preserves
audible playback; commit/cancel/stale audition and unuse release all candidate
resources; no key/render layering drift after repeated replacement.

* Phase 5 — reusable actor compute workers
Owner: upstream JS actors; PELAGIC first exercising client.
- Add actor-owned lease/job lifecycle to the existing runtime: owner, job ID,
  generation, cancellation, credit, priority, bounded inbox and result routing.
  Compiler-visible effects/ABI facts should supply defaults so package authors
  don't manually implement scheduling at every call site.
- First pool preparation/compile/analysis within one browser realm. Bound
  pool capacity from measured CPU contention; keep a fallback for no workers.
- Refactor preparation from one initialization/job id 1 to isolated reusable
  jobs. Clear per-job actor state/caches/callbacks and prove that job B cannot
  observe job A. Return a healthy worker only after reset acknowledgement.
- Use cooperative bounded actor turns for cancellation; terminate and replace
  a worker that fails to yield. Distinguish requested cancellation, rejected
  stale results and actual cessation of CPU use in measurements.
- Move reserve/admission/fairness policy into BL modules using canonical JS
  lowering. Preserve playback's reserve across compile/export/analysis bursts;
  prevent starvation among sessions and cap speculative queue bytes/jobs.
- Keep AudioWorklet and canvas/GL ownership dedicated initially. Transferred
  canvases, GPU state and audio device timelines are not generic pool leases.
- Cross-tab SharedWorker is an optional later prototype, gated on browser
  support, isolation and transfer costs; not required for this phase.
Accept: two sessions and repeated jobs reuse workers without cross-talk;
unuse cancels only the owning jobs; crashes recover; worker and retained-byte
counts plateau over 100 cycles; preparation outputs match existing digests.

* Phase 6 — pressure tests, audio/video and code consolidation
Owner: all three layers; final integration commits and documentation.
- Measure cold/warm startup, edit-to-candidate, audition-to-commit, CPU, memory,
  queue delay, worker startup, cancellation latency and audio reserve minima.
- Stress playback with competing exports, compiler jobs, analysis and repeated
  two-session load/unload. Run graphics worker and main-thread fallback paths.
- Separate scheduling CPU time, AudioContext output timing, displayed-frame
  acknowledgements and physical sound/display latency. Browser clocks alone
  cannot establish physical A/V P95. Specify physical capture equipment and
  repeatable stimulus before reporting the desired <=16 ms result.
- Record P50/P95/P99/max and dropout counts on declared hardware/workloads.
  Use 16 ms as the desired physical latency budget, not an excuse to remove
  buffering blindly. Document device/browser floors and unresolved tails.
- Profile FFT allocation/trigonometry and compile/prep bursts; add reusable
  plans/buffers in BL-generated JS where profiles justify them. Keep browser
  WebAudio/WebGL/file APIs as thin annotated interop adapters.
- Remove superseded package installers, worker schedulers and local compiler
  paths only after consumers migrate. Audit remaining ordinary/actor pipeline
  duplication against PLAN-014; don't call consolidation complete prematurely.
- Documentation: concise root quickstart, package author example, actor-owned
  job example, ownership diagram, cache invalidation rules, reload limitations,
  benchmark reproduction and live-world safety instructions.
Accept: Omega tests, package/editor drive tests, unchanged presentation check,
real used/unuse screenshots, audible two-session proof, demo export integrity
and comparable performance report. Record honest follow-ups for unmet latency.

* Delivery order and commit policy
0 -> 1 -> 2 -> 3 -> 4; phase 5 can follow 2 after actor ABI audit, with phase 6
closing every branch. Prioritize warm dispatch and declarative assembly before
the expensive incremental compiler and worker sharing work.

Each phase ships reviewable upstream commits for generic infrastructure,
followed by Omega integration commits and pin changes to committed revisions.
Update this plan's checkboxes and proof links with each completed slice. Keep
unrelated dirty work untouched; no automatic upstream push implied by commit.
For upstream execution follow AGENTS.md: inspect scripts/bl-mem, one owned BL
VM job at a time, memory-cap long jobs and stop owned services after checks.

* Decisions intentionally deferred until evidence
- Whether measured warm scans need a process-local digest index; retain full
  verification at trust boundaries and don't substitute timestamps for hashes.
- Whether hot code replacement is worth its state/module retention costs;
  explicit session reload remains correct for unsupported changes.
- Whether cross-tab pooling saves more than transfer/reset overhead.
- Which changes need native lowering: profile first; native cannot eliminate
  browser device/GPU latency and must preserve the same actor/interop contracts.
- Exact friendly-domain/TLS setup and worker count depend on the existing
  gateway and target browsers; prove these before making them defaults.
