#+title: Beam Lisp runtime observability — complete upstream cutover
#+status: IN_PROGRESS
#+date: 2026-10-11

* Purpose and completion contract
Replace the Runtime observatory prototype's application-owned runtime machinery
with standard Beam Lisp ownership, actor, observation and discipline facilities.
Omega composes the interface and world/task projections; Pelagic contributes
application diagnostics. Ordinary BL namespaces inherit inspection automatically
from their runtime participation, without maintaining a second registration or
optimization specification.

This is a complete production cutover, not an optional competing backend.
Finish means migrated consumers, deleted superseded implementations, documented
contracts, reproducible evidence and a pinned release that runs from root env.bl.
Do not label a scaffolding implementation or unperformed proof as complete.
Implementation approved by the user; editor work stays in the existing vendored
bl-ed here. Moving or integrating bl-ed into Beam Lisp is explicitly out of scope.

* Non-negotiable architecture
One reader, checked ANF, canonical value/callback ABI and actor execution model.
Direct same-realm native JavaScript calls specialize that model. Actual Worker
and tab boundaries use real messages/transfers and explicit ownership; an
inspector must never introduce a mandatory transport on local calls.

Authority remains with the owner of the actual resource. Observation is a
bounded read projection, not another process registry or a scheduler. A remote
report cannot grant cancellation or restart authority. Shared physical VMs do
not make different projects, worlds, tabs or generations interchangeable.

Unknown evidence remains unknown. A synchronous function is not necessarily
pure, cheap, terminating, worker-safe, or capable of meeting a 16 ms deadline.
No copying of full mailboxes, arbitrary environment values or payload contents.
No writes to the user's world on port 8790; test private offline memory worlds.
Preserve concurrent changes, cap BL jobs and stop owned test processes.

* Ownership of the final code
| Concern | Final owner |
|---------+-------------|
| Process identity, ownership, monitors, links, runnable/mailbox counters | Beam Lisp actor/runtime modules |
| Scoped read projections, observations and subscription lifetime | Beam Lisp standard libraries |
| Admission, cancellation, execution and job lifecycle | Existing proc facilities, extended only where needed |
| Interop/effect/suspension/transition evidence | typed and system modules over canonical checked IR |
| Browser DOM, Worker, channel and clock operations | Small bounded JS interop namespaces/host leaves |
| Generic inspector package and frame integration | bl-ed, reusable without Omega imports |
| World/task/catalog/host-generation projections and root tasks | Omega |
| Audio reserve, audition, preparation, graphics and revision meaning | Pelagic |

The generic inspector stays a loadable package in Omega’s existing vendored
bl-ed. No editor packaging/repository migration into Beam Lisp is included. Its models and controller
are BL; imperative browser work is bounded interop. Omega adds domain adapters,
not a fork of the inspector. No application domain names enter generic ed/*.

* Phase 1 — upstream ownership and observation contract
- [ ] Define immutable resource identity: issuing runtime/session, owner,
      resource identity, kind, generation and lifecycle epoch where required.
      Do not use printable PIDs or user-visible labels as control capabilities.
- [ ] Project existing vm.owner/service/realm authority and JS actor registry.
      Include owner relationships and native worker/scheduler placement where
      known. Generic non-actor resources have owned handles tied to lifecycle.
- [ ] Define bounded snapshot and delta/subscription contracts: schema version,
      sample sequence, monotonic durations, wall timestamp, units, availability,
      truncation, staleness and dropped/coalesced update counts.
- [ ] Keep telemetry demand-driven and cheap when disabled. Consumers cannot
      block actors; bound cardinality, bytes, retained history and subscriber
      backlog. Overflow reports loss and supports bounded resynchronization.
- [ ] Scope observations to authorized realm/world/session views. Counters for
      the physical VM are explicitly distinguished from realm-owned resources.
- [ ] Define target support explicitly: BEAM/native host versus JS main thread,
      Worker and AudioWorklet. Missing counters are unavailable, never zero.
Exit: native and JS contract fixtures, identity/isolation/death/overflow tests;
no independent shadow registry holding the authoritative actor lifecycle.

* Phase 2 — standard lifecycle and browser interop
- [ ] Give ordinary proc/actor users standard lifecycle/progress observations
      through existing owners. Optional application progress is data attached
      to existing work; bookkeeping is not repeated by every caller.
- [ ] Preserve admission cancellation before execution, cooperative cancellation
      of private speculative work, and draining of accepted shared effects.
      Define outcomes, cancellation races and completion precedence explicitly.
- [ ] Preserve active ownership through history churn; bounded completed history
      cannot remove active work or weaken concurrency admission.
- [ ] Tie workers, subscriptions, timers, channels and host handles to owners.
      Define owner death, package unuse, realm close and worker failure cleanup.
- [ ] Move generic browser observation mechanics into upstream BL, using the
      existing JS namespace boundary and bl->js/js->bl conversions. Retain only
      necessary browser leaves. No extra reader or hand-maintained JS BL model.
- [ ] Treat tab reports as expiring observations with bounded validation. Same
      origin alone is not a control grant. Local controls resolve current owner
      authority at invocation; stale handles are refused.
- [ ] Extend existing worker/resource facilities where required instead of
      introducing a second pool. Preserve direct local calls and transferable
      buffers; observations must not serialize DSP or graph payloads.
Exit: owner-death, churn, duplicate cancel, timeout, stale-generation, worker
crash, teardown and disposal tests pass on every supported execution target.

* Phase 3 — disciplines and compiler evidence
- [ ] Reuse typed/system.js for native receiver and conversion diagnostics,
      known missing #js and explicit numeric-policy checks. Keep JS use bounded
      to the declared interop namespace; ordinary callers need no annotation.
- [ ] Reuse system.suspension to specialize proven synchronous calls inside the
      canonical actor profile. Test recursive and higher-order calls, callbacks,
      exceptions and unknown callees; unproved calls use the canonical safe path.
- [ ] Extend effect summaries for observation leaves. Check declared read-only
      projections and separate control effects; unknown effects stay unknown.
- [ ] Model lifecycle transitions with system.model/proc contracts. Add bounded
      model/property checks for active ownership, terminal transitions and
      generation publication/cancellation races. Runtime enforcement remains
      necessary for dynamic limits, owner liveness and authority.
- [ ] Carry source/generation/proof provenance with compiled definitions so the
      inspector explains evidence without reanalyzing on each sample. Consume
      existing publication evidence only for the properties it actually proves.
- [ ] Infer from ordinary BL code and existing declarations wherever possible.
      Do not require per-function telemetry registrations or duplicated policies.
Exit: positive and negative fixtures show exact diagnosed properties; unknown
cases never acquire a fabricated proof. Compiler passes preserve language and
interop semantics on both targets. No general hard-real-time proof is claimed.

* Review decisions already settled
Prefer ordinary namespace code and inferred evidence over new annotation syntax.
Reuse ownership and proc semantics rather than upstreaming prototype machinery
unchanged. Keep mechanisms upstream and domain meaning in Omega/Pelagic. Local
demos remain optional packaging of the same application. Do not add universal
remote process killing, cross-tab control, or runtime restart UI to this cutover.
API naming is finalized in phase 0 against actual upstream exports, not invented
in advance. Physical 16 ms remains an explicitly measured goal, not a promise
that static analysis or this observability cutover can certify by itself.
