#+title: PELAGIC as an Omega session package
#+status: DONE

* Contract
Root env.bl exposes pelagic.dev, pelagic.local and pelagic.bundle. One compiler
pin and one JS frontend graph. Launching must not package a ZIP or overwrite
vendor/bl-ed/web. Use the existing bl-package and per-editor package ownership.
Reuse a compatible development host; reject a conflicting listener without
writing to it. Never test against the user's world on port 8790.

* Steps
- [X] Unify compiler selection and expose root tasks.
- [X] Extract cached frontend compilation from standalone export.
- [X] Launch Omega with the frontend directory directly; reuse compatible host.

- [X] Verify compilation/cache invalidation, host reuse, two sessions, unload,
      audio, package/editor tests and presentation equivalence.
- [X] Document commands, ownership and remaining realm/incremental work; commit.

* Scope
Existing editor sessions already load packages by query/use. This change builds
on that path. It does not invent a new realm scheduler, share mutable editor
state across sessions, or claim module-level incremental compiler support.
