* 1. Join the existing launch path
Keep root env.bl as the declaration and omega.dev/acquire! as the owner.
Add Pocket as a package/layout preset of that host. A proposed =bl pocket=
task delegates to the same entry as =bl omega.dev=; the exact task name is a
convenience, not another runtime. Preserve the existing explicit live/offline
choice; a durable working host must not silently reuse an in-memory demo.

Use one configured world store for tasks, places, references and buffers.
Attach project directories as places in that world; selecting another project
changes task context, not the world or application realm.

Move the existing Pocket backend setup into the common host lifecycle:
1. Install the existing place/link/buffer schema when opening the world.
2. Start the buffer service before creating the task system; give tasks its
   existing file port so agent edits and editor drafts share buffer history.
3. Install workspace providers and intents against that same system. Preserve
   context resolution for task/open, including package-profile task creation.
4. Recover tasks once. Stop admission and owned requests/work, then close buffer
   resources and storage in their dependency order through the host owner.

Use the smallest startup seam needed in omega.ed.main. Keep place.*, links.*,
buffer.* and ws.* as the domain implementations. No extra service manager,
device ownership system or per-package world.

Declare Pocket and its required editor packages in the existing packages/*.edn
frontend metadata. Build their union with omega.frontend and the existing
immutable publisher. Replace mobile's installer and separate live launcher
with delegation to root tasks. Audit bin/omega and bin/omega-ui as remaining
independent backend starts; route their supported task operations to the common
world before retiring duplicate startup paths. Preserve caller working directory.
Isolated test runners and portable demo exports keep their own intended roles.

Existing Pocket and project stores may contain different history. Inventory
them read-only before choosing the authoritative store for live use. Preserve
the others; if history must be combined, specify and test an offline import
with entity-reference and ID remapping. Do not copy databases over each other.
No live store or enabled service is changed as part of this plan.

Accept: desktop, phone and shell operations reach the same task IDs, facts and
buffers. Repeated launches reuse one host. Opening or closing a view has no
effect on other devices' tasks. Trusted Tailscale access reaches this host.

* 2. Context is ordinary world data
Use the existing vocabulary:
| Value | Meaning |
|-------+---------|
| Place | Name, optional parent, directory, home document and settings |
| Task | Goal, saved working directory, place and originating document/block |
| Reference | An input, output or background document/block attached to work |
| Session | Open panes, focus, navigation history, cursor and reading position |

The task's working directory and home document are independent. For example,
a block in a planning document can start work in another attached repository.
Opening a place does not steer a running task or change its saved directory.

Starting a task from a document retains its origin. Attach a selected passage
deliberately, with its document revision and anchor so later edits cannot change
what the model was given. A reference is navigable context; the model's request
contains the material actually resolved for that turn. Do not make every open
pane an implicit prompt input.

Tasks, answers, documents and references are shared. Session navigation can
differ across devices. A phone reconnects to the same task; there is no device
handoff or "continue here" action. Resume interrupted model execution only
through the existing recovery semantics, without replaying uncertain effects.

* 3. Everyday interactions
Implement these as documents, pure bl-ed packages, layouts and contextual
overlays over the same commands. Pocket retains full live-image/evaluation
access and the command interface; phone controls are additional entry points.

| View | Interactions |
|------+--------------|
| Work | Browse places/tasks, find unresolved questions, start work |
| Task | Read activity, answer, steer/cancel, inspect changes, open results |
| Document | Outline, search, follow links, select, edit/publish, return |
| Context overlay | Inspect directory, origin and input/output references |
| Command overlay | Discover relevant actions and inspect/evaluate live Lisp |

Reading must work independently of a conversation: open a long result, navigate
headings, select a passage, ask/start work about it, follow a reference, and
return to the retained reading position. Keep drafts when navigating or losing
connectivity. Surface a real publish conflict without overwriting either edit.

Attention is a projection of existing tasks, asks and results. Answering on
one device updates the unresolved item on the other. Define shared resolution
separately from any per-human seen/snoozed state before adding those features.
External notifications can follow once attention behavior is proven in-app.

Follow guidelines.bl.org: use placement, typography, spacing and restrained
visual accents to convey kind, emphasis and state. Keep copy minimal; retain
necessary errors and accessible labels. Discoverability comes from visible
contextual actions and a consistent command overlay. Visual refinement belongs
to the later UI pass; this pass defines behavior and its proof.

Connectors supply addressable documents/objects and existing intent operations
that can be attached as references. Reuse the current provider and intent
contracts. Native phone/desktop hosts can later add share/open/notification
affordances around the same world. Nix/Foundry packaging follows the working
root launch declaration. Security design, new connector infrastructure and a
replacement network protocol are outside this trusted-computer MVP.

* Implementation record
The implementation follows the four clusters above. The shared host now owns
places, references, attributed buffers and task-context resolution. Pocket is a
root task and immutable frontend preset; compatibility launchers delegate to it.
The shell is an HTTP client of that world. No live service or store was changed.

Document reading, checked selection snapshots, the command/prompt overlay and
trusted machine evaluation are implemented. Reply resolution is idempotent;
task admission failures become terminal facts. Closed tasks retain their history
without offering an actionable question. Browser reply drafts survive tab reload
and native text selection remains usable for Copy.

The actual root-launch browser test exposed a Beam Lisp supervisor gap: an OTP
supervisor started children in its own environment rather than the child spec's
owning environment. Upstream commits df06ff03 and b7837470 fix conveyance and
publish its regenerated bootstrap floor. The supervisor ABI and conveyance tests
pass 137 assertions; =bl seed --check= verifies the generated floor.
