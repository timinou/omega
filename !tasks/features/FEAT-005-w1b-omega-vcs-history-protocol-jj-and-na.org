* Goal
**Revised by the spikes (bl-ed.bl.md §15.1–15.2; E6′, E17′, E22, E23).** History is beam-lisp native from day one: one implementation, `omega.history`, built from spikes/history.bl.md. jj leaves the plan; jj/git become import/export only (FUP-008). The five-verb protocol remains as the CONTRACT SUITE, the test the autovcs redesign must pass.

What the spike proved, on the durable store:
- **Objects.** Content-addressed `{:text :origins}`, so line blame is written at checkpoint time (1.8 ms to read for 400 lines).
- **Changes.** Immutable facts with who/why/when/gate/conflicts/renames; a keyframe every 32 steps.
- **Refs.** Append-only move facts (a hot ref entity made every checkpoint slower).
- **Operations.** Three-way merge with conflicts as data; revert-by-merge preserving blame; rename following.
- **Cost.** ~55 ms p50 per checkpoint, flat over 1200 steps.
* Scope
- `omega/history.bl.md`, ported from spikes/history.bl.md:
  - the store (`open checkpoint! head log diff blame tree-at text-at branch! merge! revert!`) runs in ONE historian process (a defserver). Its memos live in that process's dictionary, because changes are immutable and so cacheable forever.
  - Without one owner, spikes/step-checkpoint.bl.md observed forked history (2 of 6 changes reachable).
- The checkpoint is a `:tool/after` HOOK (E22), never an `:on` event. Events run in spawned processes after the task moved on, so they skew and lose steps (3–5 of 6).
- The hook records only the files the stepping task WROTE (E17′).
  - Attribution comes from the writer: `write`/`edit` (through the C6 file port) report task + path + exact text to the historian.
  - Not from claims, which cannot split two tasks' hunks in one file.
  - Files changed by `sh` are found by a working-tree diff and attributed by L0 adoption (reap tags), else to actor `disk`.
- **Gate per path (E23).** A change is gated on the files it carries; a failing gate still records the change (`:gate :fail`), leaves a `:finding` and turns the card red (E18).
  - spikes/task-refs.bl.md: per-path gating never failed B for A's broken file (0/5); gating head ∪ my files did.
- **Optional per-task refs.** Branch at task open, merge into main at idle/done; conflicts become a finding plus needs-input.
  - They give per-task blame across merges.
  - They do NOT give test isolation: that is E17 (b).
- The contract suite in `omega/history/test.bl.md`: the spike's behaviour block as assertions, plus the gaps as they land (fuzzy renames, binary files, criss-cross merge-base, indexed log).
- Upstream nothing to jj. beam-lisp's autovcs redesign starts from this namespace.
* Acceptance
- The contract suite is green.
- A 3-step scripted task records exactly 3 changes, each carrying only that task's files, with `why` = "<goal> · step n" (no skew in 10 runs, two concurrent tasks).
- A failing gate records `[gate ✗]` plus a finding on the task that wrote the broken file, and never on the other task.
- `log {:by t}` and blame answer in < 50 ms at 1000 changes.
- p50 checkpoint < 100 ms on the durable store, flat over 1000 steps (needs C8 so the hook's surroundings stay flat too).

* Async checkpoints (spikes/async-checkpoint.bl.md, 2026-10-03; E22 refined)

The `:tool/after` hook SNAPSHOTS the texts the step wrote (inline) and `cast`s `[:snap task step why {path text} gate]` to the one historian, which commits in arrival order.
- **Observed.** 0 skew, 0 misattribution and 0 per-task order errors (5/5 runs); per-task histories identical to the blocking variant; task-side cost ~5 ms p50 vs 70–130 ms blocking.
- **Hook implementation:**
  - Drop `task/view` from the hook (~3 ms of the 5).
  - Record written paths inside `write`/`edit` (with C6's port, or next to the existing claim), into a small per-task write buffer the hook drains. Not the cell's process dictionary: cells are separate processes.
  - A `:sync` option blocks the hook until commit, for gates that must hold the task.
  - Bound the historian's mailbox (a 60-cast burst queued 59; throughput 27–36 commits/s) and add `:flush` for tests and shutdown.
- **Gotcha.** A prelude wrapper that calls the saved original `write`/`edit` recursed and hung. Use the C6 port, not wrappers.

** Capture: trace + scan (spikes/fs-capture.bl.md)

*** The trace

`codemode/run-eval`'s preamble starts `erlang:trace` on the cell process: `[call, set_on_spawn]` with a per-cell collector, and VM-wide trace patterns on the `file`/`prim_file` write, rename and delete exports and on `erlang:open_port/2`.
- After `eval-cell` returns: `erlang:trace_delivered`, then take the events.
- The events give `claims` (written, deleted, renamed paths) and `os?` (any `open_port`).

*** The scan, only when `os?`

- One stat walk of the root, skipping `.git .omega _build node_modules target`; `.gitignore` later.
- Diff against the previous after-scan, kept in a cache server, using Erlang `maps/*` functions: beam-lisp `filter`/`=` over 2,000-key maps is 15 ms to 1.8 s.
- Hash only changed paths. Racy rule: hash any entry whose mtime ≥ scan second − 1 (mtime has one-second granularity).
- Renames are paired by inode.
- Cap changed paths per step (~500) and record `:truncated`.

*** Per-path record

- `:source :trace` — exact.
- `:source :scan` — the only OS-process cell in its window.
- `:source :scan :ambiguous [tasks]` — overlapping `sh` cells.
- `:source :external` — no omega cell running.
- Renames are `[from to]`; a delete is a path with nil text.

*** Cost and limits

- Pure-BEAM cells cost under 1 ms. An `sh` cell costs ~60–140 ms per 2,000 files, run in the cell process or the historian, never in the task-side 5 ms.
- Known misses: create-then-delete inside one `sh` eval, and writes outside the root.
- Opt-in for exactness on `:ambiguous` paths: `strace -f` (3–31× slower).
- Rejected: inotify, overlayfs.
- Use one trace collector per cell: a shared one misattributed everything in the spike.

** Beam-lisp projects: the :image part (spikes/live-image.bl.md)

*** The :image part of a change

`{:vars {ns/name {:hash :prev}} :reloaded [ns] :gate {:ward …}}`. Var hashes are of the position-stripped source form. Never hash the compiled AST: gensyms and module names differ on every eval. "Removed" comes from `own_names`, because plain eval never removes a var. File edits get it from the file's new text; eval cells get it from their source.

*** Opt-in reload on checkpoint

- Policy `:omega {:reload :on-checkpoint}`, off by default.
- `reload/commit` of the touched namespaces, never when the gate failed; recorded as `:reloaded`.
- Dev image only: reload refuses in a release image.

*** Ward gate for beam-lisp steps

- Use `reload.ward/run-sandboxed` ONLY: ~80–110 ms warm; warm the test library at task start, cold is 7–8 s.
- A lint refuses `ward/run` / a same-ns `env/fork`: both leaked into the live image in the spike.
