* Goal

The document grammar learns cell kinds as data, so `#+begin_task` is a cell when the package is loaded and prose when it is not (§3.5, §10.1).

* Scope

- beam-lisp `bl.doc.spans`: `:cell-kinds` in opts; a registered `#+begin_<kind>` → `{:kind :cell :cell-kind k …}`; header tokens parsed by `src-attrs` rules.
- `bl.doc` runner dispatches evaluation by kind.
- `write-results` inserts a result after any cell (today only after `:cell`, doc.bl:396 `insert-new?`).
- Both targets (BEAM and the JS sync profile) share the scanner.

* Acceptance

- Without the kind registered, today's partition (`:block` + `:result`) is unchanged.
- With it, the block is a cell, and a first evaluation inserts `#+RESULTS: <id>`.
- The BEAM and JS selftests agree.
