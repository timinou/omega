* Goal

One defserver per file in use, owning its text, its revisions and its op log as datom facts in omega's store (§5.1–5.8). Spikes 1 and 2 in bl-ed.bl.md become the package.

* Scope

- `omega.ed.buffer`: ops `[from to text]` on `[row col]`, rebase over unseen ops, per-actor cursors; one transaction per op with `:tx/actor :tx/cell :db.valid/from` (§5.5); content CAS refusals that name who moved it.
- `:revert-cell` (compensating ops, refused as data).
- A buffer-backed file port (C6) installed by the package.
- Disk publish: agent ops immediately; human batches on pause ≈1.2 s, motion, `C-s` (E5).
- L0 adoption: disk changes no buffer saw are diffed in, attributed via reap tags, else actor `disk`.
- Known gaps carried as FUPs: same-position inserts (FUP-003), log compaction, grapheme columns.

* Acceptance

- Spike 1's and spike 2's OBSERVED outputs reproduce as tests against the package namespace.
- An agent `edit` through the port lands as an op tagged with its C4 cell id.
- `as-of` the op's tx returns the file text at that moment.

* Spike results (2026-10-03, bl-ed.bl.md §15.3–15.4)

- **Op model: use spikes/convergence.bl.md, not §5.3.**
  - §5.3's `transform` diverges on 63% of random concurrent pairs.
  - The fix that reached 0/6000: atomic ops (replace = delete + insert); a transformed op may split; an actor tiebreak for same-point inserts; `shift-end` for delete ends; a list-vs-list transform (`tl`). The code is `atomize` / `t1` / `transform3` / `tl` in that spike.
  - So: log entries are op lists, ops carry an actor, and the `:op` reply is a list.
  - Port the spike's seeded 2000-case property test into test/ as the acceptance test.
- **Publishing (E24).** A disk publish writes only *published* ops. The human's unpublished ops are an overlay that agent reads see but disk does not. spikes/file-port.bl.md observed an agent publish writing the human's half-typed line to disk.
- **The server reuses `prelude/apply-edits`** for `edit`, so error text matches: ":old not found …; changed since you read it (rev N): <task> in cell <cell> at rev M".
- **Buffer state lives in the server process.** Never in an atom: a beam-lisp atom deref copies the whole value.

* Overlay semantics (spikes/buffer-overlay.bl.md, 2026-10-03; E24)

Verified 0 violations over 3×500 random cases. Implement exactly this:

- **State.** `pub` (== disk text); per human actor `pend` (atomic ops based on pub) and `ovlog` (landed ops in that actor's view coordinates).
- **`[:human-op actor base ops]`.**
  - Atomize the ops, then `tl` them over `ovlog[actor][base..]`, and append to the actor's branch.
  - Reject `base > rev`.
  - Validate by applying to pub; return `:invalid-op` rather than crash.
- **Landing (a publish or an agent edit).**
  - Apply to pub.
  - Transform the landed ops over every other branch, and append them to each `ovlog`.
  - Write disk.
- **Agent edit.**
  - Applies to PUBLISHED text.
  - A replace is encoded as insert-new-at-end-of-old, then delete-old, so a pending insert at either edge keeps its side.
  - `:old` must occur exactly once in the view and once in pub. Errors: `:not-found`, `:ambiguous`, `:overlay` (old exists only in an unpublished overlay: refuse), `:published-ambiguous`.
  - A self-check (new view == old view with old→new) turns a disagreement into `:conflict` with nothing changed.
- **Reads.** `read` = pub ⊕ branches merged with `tl` in sorted-actor order; `own` returns `{text rev}` as the client's base.
- **Performance.** Cache the view per revision in server state: 6 pending ops made reads 0.5 ms and agent edits 5.5 ms.
- **Not covered:** ≥3 humans' view order, pipelined client sends (needs a per-op base or an ack-serialised client), disk write errors.
