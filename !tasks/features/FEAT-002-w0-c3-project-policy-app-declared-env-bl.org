* Goal

Let a project's `env.bl` carry an `:omega` section (and any app's section), validated by the app, while `bl.env` still refuses typos. Answer to the user's 'shouldn't that be in the omega config?': three layers with one owner each (§8.4.1, E20, E21).

* Observed

`bl.env/normalize` refuses `{:omega {…}}` ("unknown key omega") and also `{:apps {…}}`, a key realm's own `vm.spec` reads (spec.bl:122): an existing inconsistency.

* Scope

beam-lisp:
- apps declare `{:key :ns :validate :doc}` as data (an `:extends` entry, or discovery on `:paths`);
- `bl.env` dispatches declared keys to their validator, merges its errors into `:errors` named by key, warns (not errors) when a validator can't load, and keeps refusing undeclared keys;
- `:apps` becomes a built-in declared key.

omega:
- new `omega.config`: `validate`, defaults, `read` (precedence: omega defaults < `~/.config/omega/config.bl` < project `env.bl :omega` < project `.env.local.bl :omega`, deep merge as `vm.spec/overlay`);
- keys: `:journal :profiles :vcs {:backend :per :gate} :idle :card :attention`;
- secrets stay in `.env`/process env.

* Acceptance

- `{:omega {:journal "journal"}}` validates; `{:omgea …}` is still an error; a malformed `:omega {:idle "x"}` reports a named error; `{:apps {…}}` no longer errors.
- `omega.config/read` precedence covered by a test with all four layers.
- `bl realm show` can print the project's `:omega` section (or a FUP if realm's show isn't extensible yet).
