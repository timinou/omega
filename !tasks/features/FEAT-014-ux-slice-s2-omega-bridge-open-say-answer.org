* Goal

bl-ed (another VM) can open, steer, answer and watch omega tasks, and read/write the virtual scratch pad (ux-slice §3.3, §2.7).

* Scope

New `src/omega/ed/bridge.bl` (no change to omega core namespaces):
- `POST /open {goal scope}` → `{id}` via `task/open!` (existing keys only). Without a cell (homeless), also append `* <title>` + `#+begin_task :id <id>` / goal / `#+end_task` + `#+RESULTS: <id>` / `: #omega/task {:id … :goal <digest>}` to the scratch pad.
- `POST /say {id text}` via `task/say!`; `POST /answer {msg choice}` via `actor/reply!`.
- `GET /tasks?ids=…` → `{id row}` from `omega.ui.model/task-row`, plus `:summary` (`:task/result`) and `:touched` for terminal tasks.
- `GET /scratch` → `{text hash}`; `POST /scratch {text base}` → `{ok hash}` or 409 when base ≠ current hash. Stored in `.omega/scratch.bl.org` (gitignored). The first GET seeds `#+TITLE: omega scratch — tasks with no home`.
- `bin/omega serve`: start the world + bridge on loopback, write the URL to `.omega/url`, remove it on exit.

* Edge

- Loopback only; JSON bodies; unknown task ids answer `{}` rows, not errors.
- The scratch append and a human save race: both go through the base-hash check; the append retries on its own fresh read.

* Acceptance

- One test with a scripted model: open → poll shows :running → the model asks → poll shows the ask → answer → done, with the summary in the row; all over HTTP.
- Scratch: homeless open appends exactly one task block; a stale-base POST gets 409.
- omega's full suite stays green.
