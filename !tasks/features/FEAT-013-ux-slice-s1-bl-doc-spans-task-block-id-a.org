* Goal

A `#+begin_task :id hex` block gets a result span written after it by the one shared writer, so bl-ed can put the `#omega/task` reference line under a task block (ux-slice §3.1).

* Scope (beam-lisp `priv/std/bl/doc/spans.bl`)

- `org-span-at`: a `:block` span reads `:id` from its header with the same rules as `src-attrs` (`:explicit-id`). Markdown is out of scope (task blocks are org only).
- `write-results`: a missing result for an id is inserted directly after a `:block` whose `:explicit-id` equals it, exactly as after a `:cell` (org: no extra blank; keep the parse→write→parse fixpoint).
- `assign-ids` is unchanged: blocks never become cells, so `bl.doc/cells` and the document's program are unchanged (FEAT-006's revised rule).

* Edge

- A block without `:id` gets no result (the console always writes an id, E25).
- An existing `#+RESULTS: hex` after the block is rewritten in place (already true).
- A `:cell` and a `:block` with the same id: the cell wins; test it.

* Acceptance

- New tests in the spans test file run on BEAM and on JS (the selftest/differential that already covers spans).
- `bl doc run` on a document containing a task block produces identical cells, program and results as without the change.
- Supersedes upstream item 1 of FEAT-006's revision.
