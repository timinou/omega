# Normal Play and continuous PERFORM

The normal Play action (`g p`) and continuous PERFORM both use the same audio
engine. Normal Play resets the stage to its compiled base shader before scheduling
the finite score. The graphics worker proxy omitted the `baseSource` property
available on the main-thread stage, so that reset compiled JavaScript `undefined`
as GLSL. The resulting `ERROR: 0:1: 'undefined' : syntax error` escaped as a
`package-host` error before the scheduling timer started: the audio context was
running, but zero voices had been triggered.

The worker proxy now exposes the validator's current base source through a getter.
It preserves the existing stage contract without copying the shader or adding a
second source of truth. Subsequent shader replacements remain visible through the
same getter.

`python3 spikes/pelagic/test/play-browser.py` drives the real editor on an isolated
static origin. It starts normal Play, switches to PERFORM, and returns to normal
Play, with both worker and main-thread graphics. Every start must produce a
non-silent monitor signal and the expected transport mode. It also unloads the
package, checks resource disposal, and checks that source is preserved.
