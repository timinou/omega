* 0.1.1 — Work port correction

The previously supplied 0.1.0 APK contained an older compiled connection
validator that rejected Work's port 18001. Its signature and checksum were valid;
those checks did not establish that the current app source had been packaged.
This release compiles the current app and raises versionCode to 2026101601.
It uses the same signing identity, so it installs over 0.1.0 with settings retained.

The artifact gate checks the compiled app modules inside the APK and rejects
the old validation message. A host VM loaded the release's actual app and runtime
modules without app source paths: Work's 18001, default, 8443 and 65535 ports
were admitted; HTTP, external hosts, port 0 and port 99999 were rejected.
The host substitutes only the host-architecture lazy_memo NIF for that check.
This is a packaged-code check, not a physical ARM64 device execution claim.

The current Beam Lisp checkout failed during bootstrap. A private builder uses
d9e87831 with the three committed standalone packaging files from def50332
(android.bl.md, BlRuntime.kt and cli.bl), plus the existing host NIF. The pinned
Zig binary was unavailable, so native ARM64 libraries were reused from the signed
0.1.0 APK. Eight freshly compiled app modules overlay its tested complete runtime;
every other runtime entry stays byte-identical. app_bundle.py implements this
bounded app-only update and refuses a changed module set. The Gradle Android
shell is rebuilt and signed normally. No server configuration changes are needed.

Recreate that app-only bundle, after compiling the app with the matching builder:

#+begin_src sh
cd spikes/mobile/android
python3 app_bundle.py release/omega-pocket-0.1.0-arm64-v8a.apk \
  _build/android/stage/otp/omega_pocket _build/android/android/app/src/main/assets
python3 release.py
python3 test/apk_contract.py release/omega-pocket-0.1.1-arm64-v8a.apk \
  _build/android/stage/otp/omega_pocket
#+end_src

test/release_test.py checks upgrade metadata on fresh/reused Gradle projects;
test/app_bundle_test.py checks runtime preservation and incompatible module
rejection. test/packaged_home.exs checks the packaged connection behavior with
code paths extracted from the APK. The old signed APK was also passed to the
artifact gate and rejected for its old validation message.

Native journeys use an x86_64 Android 36.1 emulator. The phone APK is ARM64;
physical ARM64 hardware was unavailable. ARM translation in the x86 emulator
cannot launch BEAM's standalone helper executables, so native execution is
validated with the matching emulator ABI.

All browser and native network journeys target an offline memory world on
127.0.0.1:8792, rooted under /tmp/omega-pocket-world. The emulator's test-only
HTTPS proxy routes only to that listener, using a valid Tailscale certificate.
No test writes to port 8790 or the running Pocket server. Tailscale Serve mappings
remain unchanged.

* Rebuild
=android/setup.sh= builds and signs a self-contained release APK using Beam Lisp's
=android build --standalone --release= support. =BEAM_LISP_MOBILE_BIN= selects the
builder. This release uses source generation =d9e87831= plus the standalone
packaging changes. The signing key remains private under
=~/.local/share/omega-pocket/signing/=; it is excluded from the APK and repository.

Upstream implementation is in Beam Lisp's =priv/std/bl/android.bl.md=,
=priv/android/kotlin/BlRuntime.kt= and =priv/std/bl/cli.bl=. Runtime assets are
verified and installed before BEAM starts; upgrades preserve files outside the
bundled =otp/= directory. The Android image includes its runtime startup owner
registry, all locked libraries, the Android namespaces and the Pocket app.

The shell requests Internet and network-state permissions. AndroidX also adds
its own signature permission for internal receivers. Development distribution,
notification listeners, accessibility services, overlay services, microphone
access and the remote page's native JavaScript bridge are absent from this
release configuration.
